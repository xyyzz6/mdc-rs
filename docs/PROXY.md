# 代理与网盘接入方案（115 刮削的两条硬骨头）

> 目标：像 mdc-ng 那样的刮削器，但**重点是刮 115 网盘里的视频**，
> 并且**内置代理**、同时出 **Docker / exe / APK** 三端。
>
> 本文是这两件事的设计与落地顺序，不是已完成清单——状态见文末「进度」。

---

## 第一部分：内置代理内核

### 为什么不是「填个代理地址」就够了

刮削站（javbus / FC2 官方站）在国内直连实测 `http_code=000`，必须有出网通道。
只给一个 `proxy` 配置项的代价是：用户得**自己在别处先搞定代理**（Clash、旁路由、
另一个容器），再把地址抄过来；NAS 上部署时「再开一个容器专门做代理」是常见做法，
但这等于把复杂度丢给用户，也不好做「按站点开关」。

所以做**内置内核**：软件自己拉起一个代理内核，用户只提供订阅链接。

### 形态（已定）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 内核 | **mihomo（Clash.Meta）为主，sing-box 备选** | 市面上订阅绝大多数是 **Clash YAML** 格式，mihomo 可直接吃；sing-box 需要转换层 |
| 配置来源 | **用户自带订阅链接**，软件**不预置任何节点/订阅** | 预置节点既不可靠也不合规 |
| 托管 | mdc-server 拉起子进程，管生命周期 | 三端一致；不引入 supervisord / s6 之类额外运行时 |
| 对外 | 默认**只监听 127.0.0.1**；可选开关放开到容器网络，供 Emby / CD2 共用同一条通道 | 默认最小暴露面（与既有安全底线一致） |

### 内核二进制从哪来（🔴 不进仓库）

二进制几十 MB，且有各自的授权条款，**不放进 git**。三端策略不同：

| 端 | 来源 | 缺失时 |
| --- | --- | --- |
| Docker | 构建期从内核官方 Release 下载（构建机有网） | 构建失败（宁可失败，也不出一个"看起来能开但没内核"的镜像） |
| Windows exe | 打包脚本从本地 `tools/proxy/` 取，随包分发 | 安装目录缺文件 → 该功能禁用，UI 明示，退回「外部代理」模式 |
| Android APK | 可选；放 `lib/<abi>/` 由 App 首次启动时拷到私有目录并 `chmod +x` | 不内置 → APK 端退回外部代理 |

⚠️ **合规**：本功能只是「让用户自己配置的代理通道跑在同一进程树里」，
不提供、不推荐任何节点或订阅。使用者自行承担遵守当地法律法规与站点服务条款的责任。

### 生命周期（托管逻辑）

```
启动 ──► 订阅 URL ──► 拉取 YAML ──► 落 <data>/proxy/config.yaml
   │                                    │
   │                                    ▼
   │                         spawn 内核（-f config.yaml -d <data>/proxy/home）
   │                                    │
   │                        ◄── 轮询探测 mixed-port 就绪（超时 15s）
   │                                    │
   ├── 成功 ──► cfg.common.proxy = http://127.0.0.1:<port>
   │            并且**必须**豁免回环（net.rs 默认已豁免 127.0.0.0/8）
   │
   └── 失败 ──► 降级：沿用用户填的外部代理 / 直连，UI 显示原因，绝不静默
```

三个必须做对的点：

1. **🔴 自己别套自己。** 内核地址是本机回环，若 mdc 请求它也走代理就是死循环。
   这正是 `net.rs` 里 `DEFAULT_BYPASS` 默认包含 `127.0.0.0/8` 的原因——
   **两件事必须一起看**，单看任一半都发现不了。
2. **失败要降级而不是卡住。** 订阅拉不到、内核起不来、端口没起来，
   都要回落到「外部代理 / 直连」并**如实告诉用户**（mdc-ng 式的静默退化最难查）。
3. **订阅拉取本身可能就需要代理**（鸡生蛋）。第一次拉订阅若失败，
   允许先用「外部代理」拉一次，之后交给内核——UI 上把这两个字段分开，别混成一个。

### API 草案（都在鉴权保护区内）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/proxy/status` | 内核状态：未启用 / 启动中 / 运行中 / 失败（含原因）、监听端口、版本 |
| PUT | `/api/proxy/config` | `{enabled, subscribe_url, kernel: "mihomo"\|"sing-box", expose_lan: bool, port}` |
| POST | `/api/proxy/reload` | 重拉订阅并重载（不重启进程） |
| GET | `/api/proxy/log` | 内核日志尾部（只读，长度截断） |

### 测试策略（离线可测的部分一定要测）

| 可离线测 | 需真订阅（`#[ignore]`） |
| --- | --- |
| 配置生成（订阅 YAML → 内核 config 的字段映射） | 真拉订阅 |
| 进程启停 + 端口探测超时路径 | 真起内核 |
| **降级链**：内核失败 → 外部代理 → 直连 | 真实连通性 |
| 回环豁免（见 `net.rs`） | — |

## 第二部分：APK 端内置 CloudDrive2 引擎

### 关键前提：安卓上没有「挂载目录」

现在 `cd2.rs` 假设网盘已经挂到**本机某个绝对路径**（NAS/桌面端成立）。
**安卓没有 FUSE 挂载**，App 也拿不到 `/mnt/clouddrive`。所以 APK 端必须换输入方式。

🔴 **架构影响（这条最重要）**：网盘目录源要抽象成 trait，两种实现：

```
trait DirSource { fn list(&self, path) -> Vec<Entry>; fn read(&self, path) -> Bytes }
├─ LocalFs    —— 读本机绝对路径（Docker / exe 现状）
└─ WebDav     —— 走 CD2 的 /dav（APK 端；douyin-nas 就是这么读的）
```

`strm.rs` / `pipeline.rs` 只依赖 trait，不分端。

### 复用 douyin-nas 已跑通的那套

douyin-nas 的 APK 里已经内置了 CD2 引擎并跑通了 115，直接照抄它的结论：

| 事实 | 说明 |
| --- | --- |
| 引擎是什么 | 从 **CloudDrive2 官方安卓 APK（v1.0.5）** 的 `assets/bin/<abi>/clouddrive` 取出的**独立可执行文件**，无 JNI 依赖 |
| 怎么带进包 | 改名 `libclouddrive.so` 放 `lib/<abi>/`；**`AndroidManifest` 必须 `android:extractNativeLibs="true"`**（否则拿不到可执行文件的真实路径，这条注释在 douyin-nas 的 manifest 里是红线） |
| 怎么起来 | App 从 `nativeLibraryDir` 直接 spawn，引擎监听本机端口（19798），自带管理页静态资源（`cd2wwwroot.zip`，Web 套壳即可） |
| 冷启动窗口 | **引擎比 App 本机服务晚约 680ms 就绪**（douyin-nas 实测），这期间的「连接被拒」要**退避重试而不是计入失败** |
| 115 的正确姿势 | 用 **115open（115 官方开放接口）** 挂载，走官方配额，**风控最少**；手写 115 老接口 / Alist 都已被 douyin-nas 验证为「太容易风控」后删除 |

### 不要重复踩的两个坑（douyin-nas 已删过一轮）

1. **不要自己实现 115 协议。** 网页会话能列目录但取不到直链（大文件
   `msg_code 50028`「请使用115电脑端下载」），App 扫码会话绕不过限速。
   登录与取链一律交给 CD2。
2. **不要走本机绝对路径假设。** 见上面「安卓没有挂载目录」。

### 授权提醒

`libclouddrive.so` 约 21.6 MB，是 **CloudDrive2 的官方二进制**：
不进 git（构建期从本地 `tools/cd2/` 取，**缺失就不内置该能力**），
且**公开分发 APK 前自行确认授权**（douyin-nas 那边是用户已知并接受的现状）。

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| **P0 出网层** | `net.rs`：代理 + 内网 NO_PROXY 豁免 + 统一 `Client` 构造 | ✅ 已完成（8 条测试，含变异验证） |
| **P1a 内核托管核心** | `proxy.rs`：订阅拉取 / 配置改写 / 进程启停 / 端口探测 / 降级链 | ✅ 已完成（13 条测试，含变异验证） |
| **P1b** | server API（`/api/proxy/*`）+ 前端代理区块 | ⬜ 下一步 |
| **P2 目录源抽象 + APK CD2** | `DirSource` trait（LocalFs + WebDav）、Android 侧 spawn 引擎与管理页 | ⬜ |

> 本机限制（影响验证方式，不是阻塞）：**没装 Docker**，`docker/verify.sh` 跑不了；
> **没装 Android NDK、无 aarch64 target**，APK 编不了。这两项要么在 CI 上验，
> 要么在 NAS / 装好工具链的机器上验。
